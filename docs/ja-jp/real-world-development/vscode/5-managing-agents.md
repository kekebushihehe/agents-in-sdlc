GitHub Copilot をエージェント モードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、これらの操作やファイルの編集がリアルタイムで表示されます。差分をインラインで確認し、変更ごとに採用または取り消しを選び、エディターを離れずに追加のプロンプトを送って作業を調整・拡張できます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- 作業中のセッションに指示を出し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じるユーザー向けに、ライト モードも追加したいという要望がありました。新しい会話を最初から始めずに、進行中のセッションに指示を出して作業を広げます。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順 (調査するファイル、実行するコマンド、提案する編集) が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作と一緒にインラインで表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの操作を確認します。ファイルの読み取りと編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると、変更を採用します。
   - **Undo** を選択すると、変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッションで変更されたファイル全体を確認できます。

> [!NOTE]
> ツールの操作 (ターミナル コマンドの実行など) に許可が必要な場合、エージェントは作業を一時停止し、**Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、変更内容の要約が表示されます。

## エージェントにライト モードを追加するよう指示する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えも追加します。同じチャット セッションを続けることで、エージェントは先ほどの作業 (変更したコンポーネント、スタイルの方法、ローカル ストレージの利用方法) のコンテキストを保持します。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    いいですね。次は、ハイ コントラストの切り替えに加えてライト モードの切り替えも追加してください。ライト モードも同じ方式にし、ローカル ストレージに設定を保存して、同じ UI 領域から操作できるようにしてください。ハイ コントラスト モードとライト モードは、それぞれ独立して有効にできるようにします。
    ```

2. エージェントは前の変更を確認し、ライト モードの追加を提案します。
3. 変更が追加されるたびに差分を確認し、**Keep** または **Undo** を使います。
4. エージェントが意図しない方向 (たとえば、好みと異なる方法で切り替え UI をリファクタリングするなど) に進んだ場合は、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加メッセージを送信します。

> [!TIP]
> 作業中のセッションに指示を出す方が、最初からやり直すよりも速くなります。追加プロンプトで「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」などの調整、「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを組み込む」などの軌道修正、「両方の切り替えにキーボード ショートカットも追加する」などの範囲拡張を依頼できます。

## 作業ファイルをレビューする

変更をコミットする前に、エージェントが変更したすべてのファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ指針 (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、ローカル ストレージによる設定保持など) が反映されていることを確認します。
4. 内容に問題がなければ **Source Control** パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使い、進行中のセッションを監視して方向付けました。ファイル編集ごとにレビューし、変更を採用または取り消し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個別のファイル編集を採用または取り消しました。
- 作業中のセッションに追加プロンプトを送信して、作業を調整しました。

[次のレッスン][next-lesson]では、アクセシビリティ機能をプルリクエストとして公開し、このラボを通してローカルのカスタム エージェントが作成した変更をレビューします。
