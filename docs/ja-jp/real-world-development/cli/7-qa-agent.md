これまでに `quality-checks` スキルで自動チェックを実行し、Model Context Protocol (MCP) を使う Playwright でブラウザー上のフィルタリング動作を確認しました。次は、これらの機能を、明確な品質保証 (QA) プロセスを持つカスタム エージェントにまとめます。

このレッスンでは、次の操作を行います。

- カスタム エージェントと指示、スキル、MCP ツールとの関係を確認します。
- 再利用可能な品質保証プロファイルを作成して確認します。
- QA エージェントを選択し、フィルタリング Issue に基づく結果をレビューします。

## シナリオ

Tailspin Toys は、プルリクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テスト カバレッジ、ブラウザー上の動作を一貫してレビューしたいと考えています。カスタム エージェントを使って QA プロセスを調整し、再利用できるレポートを作成できます。

## カスタム エージェントとは

カスタム エージェントは、Markdown プロファイルで定義する Copilot の専門的な役割です。プロファイルにはエージェントの目的、指示、利用できるツールを記述します。このワークショップでは、`.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまでに使用したカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を示し、`quality-checks` スキルは繰り返し実行できるチェックをまとめ、Playwright MCP はブラウザー ツールを提供します。QA プロファイルは、要件の評価と結果の報告に、これらの機能をどのように使うかを Copilot に伝えます。既存の機能を置き換えるものではなく、別の会話も必要ありません。

## QA プロファイルを作成する

機能 PR を開く前に、再利用可能な QA プロファイルを作成します。プロファイルには、QA で実行するチェックと、その作業の境界を定義します。

1. Codespace に戻り、フィルタリングの会話が Interactive モードであることを確認します。
2. 既定のエージェントに次のプロンプトを送信し、カスタム エージェントを作成します。

   ```plaintext
   `.github/agents/qa.agent.md` に QA という名前のカスタム エージェントを作成してください。Issue と合意済みの要件に照らして機能を確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP で動作を検証し、テストのカバレッジが不足している場合はテストを追加してください。

   各要件について、根拠を示して pass、fail、blocked のいずれかで報告させてください。実装コードを変更する前に必ず質問し、変更をコミットしたりプルリクエストを開いたりしないでください。

   まずはレビューできるようにプロファイルだけを作成してください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、Copilot が意図した QA ワークフローと境界を正しく設定したことを確認します。これにより、検証だけを依頼したのにプロファイルが不完全だったり、範囲が広すぎて実装を変更したりするのを防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. フロントマターを確認します。`description` は必須です。`name` は省略できますが、指定すると分かりやすい表示名になります。
3. プロファイルの指示を読み、QA が要件の確認から始め、リポジトリの指示に従い、`quality-checks` スキルを実行し、Playwright MCP を使うことを確認します。
4. QA が根拠を示して結果を報告し、実装コードを変更する前に質問し、変更をコミットしたりプルリクエストを開いたりしないことを確認します。
5. これらの役割や制約が不足している場合は、続ける前に既定のエージェントに修正を依頼します。

## Issue を基に QA を実行する

Copilot CLI は、会話の開始時にプロジェクトのエージェントを読み込みます。プロファイルを作成した後、同じフィルタリングの会話を再開し、QA を選択します。既存の Issue と計画の内容を使えます。

1. 次のプロンプトでエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> エージェントを作成した直後は、利用可能なエージェントの一覧に表示されない場合があります。上記のコマンドを使えば有効にできます。

2. 次のプロンプトで QA エージェントに機能をレビューさせます。

   ```plaintext
   Issue と計画で決めた内容に照らしてフィルタリング機能をレビューしてください。PR を作成できる状態ですか？
   ```

3. QA エージェントの作業が始まります。
4. 完了したら、結果のレポートを確認します。

## まとめと次のステップ

ワークフローに再利用可能な専門的な役割を追加し、その結果を確認しました。このレッスンでは、次の操作を行いました。

- カスタム エージェントと指示、スキル、MCP ツールとの関係を確認しました。
- 再利用可能な品質保証プロファイルを作成して確認しました。
- QA エージェントを選択し、フィルタリング Issue に基づく結果をレビューしました。
