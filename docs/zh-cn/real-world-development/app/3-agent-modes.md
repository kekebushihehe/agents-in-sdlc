我们先为项目添加了一项小功能，但更复杂的更改需要更完善的流程。GitHub Copilot app 支持组织现有的工作流程，帮助团队用正确的方法构建所需功能。从本课开始，你将通过几节课遵循典型的智能体驱动开发流程：先从 issue 入手生成新功能，确认代码有效且功能行为符合预期，最终将更改成功合并到项目中。

> [!NOTE]
> 后续功能工作将沿用同一个会话。通常，不同类型的文件会使用不同会话或拉取请求（PR）；本研讨会会采用简化方式，以便聚焦核心概念。

本课将完成以下任务：

- 从 GitHub issue 启动新的智能体会话。
- 在 **Plan** 模式中定义要求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

继续实现此功能时，你还将更新存储库指令、自定义现有的 `quality-checks` 技能、添加模型上下文协议（MCP）验证、创建质量保证（QA）智能体并创建功能 PR。

## 场景

Tailspin Toys 的游戏目录不断增长，访问者需要按类别和出版社缩小游戏范围。待办事项中的 issue 描述了该功能，但组合筛选等细节需要在编码前确定。你将使用 Plan 模式确定这些决策，然后授权 Autopilot 在明确范围内实现功能。

## 背景

将人工智能（AI）编码智能体引入开发流程不会改变基本原则。事实上，这些原则变得更加重要。大多数开发者的工作流程大致如下：

1. 打开描述待完成工作的 issue。
2. 制定实现计划。
3. 编写并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求（PR）。
7. 代码通过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体流程会因团队和组织而异，但大多数流程都与上述步骤类似。

坚持采用标准流程，可以确保 AI 生成的代码满足既定要求，并像手动编写的代码一样经过审查。

## 会话模式

**会话模式**控制智能体的自主程度。可以从提示字段下方的下拉列表中设置模式，也可以随时更改：

- **Interactive**：你与智能体协作。智能体提出更改建议，并等待你的输入后再继续。
- **Plan**：智能体先创建计划。你审查并批准计划后，智能体才会执行。
- **Autopilot**：智能体完全自主工作，包括编写代码、运行测试和迭代，无需等待输入。

先在 Plan 模式中审查计划，再使用 Autopilot 实现。

## 从 issue 启动会话

开始前，确认星级评分 PR 已合并，并且本地 `main` 已更新。

1. 在侧边栏的 **Sessions** 下选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开现有的 **Allow users to filter games by category and publisher** issue。该 issue 已由模板预先创建，无需另建。
2. 选择 **New session**，并选择基于更新后的 `main` 创建 **new working tree**。

    ![GitHub Copilot app 中的 issue 视图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认 issue 已附加到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让智能体运行 `node --version` 和 `npm --version`。如果这两个命令在终端中有效、但在会话中无效，请检查应用的 PATH 或版本管理器设置，然后完全退出并重新打开应用。重试失败的操作和检查；不要仅仅因为智能体找不到 npm 就重新安装 npm。

## 规划筛选功能

规划可以让你在 Copilot 编写代码前审查实现方案。由于会话是从 issue 启动的，Copilot 已获得功能请求的上下文。发送以下提示：

```plaintext
实现此功能。
```

回答 Copilot 的问题，并对照 issue 的验收标准审查计划。确认计划涵盖类别和出版社筛选、无障碍控件、数据访问更改和测试。讨论尚不明确的行为，例如多个类别如何组合，或没有匹配游戏时会发生什么。

计划应使用项目现有工具运行 lint、单元测试、端到端（E2E）测试和类型检查。将范围限定为筛选功能的实现和测试；完成质量工作流后再创建 PR。批准前请先要求 Copilot 修改不合适的计划内容，并保留 issue URL 和已达成一致的说明，供后续验证使用。

## 明确批准 Autopilot

对计划满意后，选择 **Approve and implement this plan**，或当前版本中的等效选项。不要假定批准计划会自动切换模式；请确认活动模式指示器显示 **Autopilot**。

Copilot 会开始实现功能，按照既定计划逐步推进、生成代码并运行测试。

> [!NOTE]
> 批准后可能立即开始实现，因此请先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决设置问题，再将检查视为已完成。只停止自己启动的服务器。

## 审查并验证实现

生成的代码与其他代码一样，需要在合并前审查。现在检查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能实现和测试。
2. 根据 issue 和已批准的说明（包括多类别和出版社组合）比较实现结果，并确认更改遵循现有存储库指令。
3. 查看 lint、单元测试、E2E 测试和类型检查的输出。跳过的检查不能算通过。
4. 接受实现前，解决失败项并重新运行受影响的检查。Playwright 的 E2E 配置会构建并提供预览服务，也可能复用本地服务器；确认被测服务器属于此工作树，而不是之前课程启动的服务器。

## 探索新功能

代码看起来没有问题，但能否正常运行？像之前一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示，让 Copilot 启动应用并在浏览器画布中打开页面：

    ```plaintext
    启动应用并在浏览器画布中打开。
    ```

2. 稍等片刻，应用将启动，Copilot app 内会打开浏览器窗口。
3. 选择一个类别，确认结果与类别相符。清除筛选，再选择一个出版社并确认结果与出版社相符。
4. 组合类别和出版社筛选，并根据 issue 和已批准的计划检查结果。如果支持多个类别，还要验证已商定的组合行为。
5. 测试一个没有匹配游戏的筛选组合并检查空状态。清除或重置筛选，确认完整列表恢复。
6. 完成后，使用以下提示让 Copilot 停止为此会话启动的开发服务器并关闭浏览器画布：

    ```plaintext
    停止开发服务器并关闭浏览器画布。
    ```

## 为后续课程保留此会话

暂时不要创建或合并筛选功能 PR。请保留此会话、工作树和分支，供第 4 到第 8 课继续使用。接下来会将自定义指令应用于筛选代码，再添加技能和 QA 改进，最后在第 8 课创建并合并合并后的 PR。停止开发服务器后，可以让会话保持空闲；下一课继续使用同一会话。

## 总结和后续步骤

你使用不同的智能体模式构建并审查了功能。本课中，你：

- 从 GitHub issue 启动了新的智能体会话。
- 在 **Plan** 模式中定义了要求。
- 使用 **Autopilot** 模式实现了新功能。
- 审查了代码。
- 在浏览器画布中手动验证了功能。
