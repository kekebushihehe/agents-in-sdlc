使用 GitHub Copilot 智能体模式时，它会自主探索代码库、提出更改、编辑文件并运行命令。由于这些工作会在本机实时进行，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。你可以内联审查每项差异、接受或拒绝单项更改，还可以通过后续提示引导对话、改进或扩展工作，全程无需离开编辑器。

本练习将完成以下任务：

- 实时监控无障碍智能体的工作。
- 审查并接受建议的文件编辑。
- 在会话进行中引导智能体，添加与高对比度模式并列的浅色模式开关。

## 场景

你在[练习 4][previous-lesson]中使用的无障碍自定义智能体正在实现高对比度模式。工作进行期间，设计团队又提出了一个要求：他们也希望为觉得默认主题太暗的用户添加浅色模式开关。不必从头开始新对话，可以引导现有会话扩展工作。

## 监控 Copilot 的进度

Copilot Chat 视图会显示智能体执行的每个步骤，包括探索的文件、运行的命令和提出的编辑。每项文件编辑都会在聊天中内联显示差异以及 **Keep** / **Undo** 控件。

1. 返回练习 4 中使用的 Copilot Chat 视图。
2. 智能体工作时，滚动聊天记录并查看工具调用。你会看到文件读取、文件编辑，以及它请求运行的终端命令。
3. 智能体提出文件编辑时，差异会以内联方式显示：
    - 选择 **Keep** 接受更改。
    - 选择 **Undo** 还原更改，让智能体重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看智能体在本次会话中修改的完整文件列表。

> [!NOTE]
> 如果工具调用请求权限（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你认可的命令。

5. 等待智能体完成高对比度模式。完成后应会显示总结所做更改的最终消息。

## 引导智能体添加浅色模式

高对比度模式就绪后，可以在同一对话中继续添加浅色模式开关。由于继续使用同一聊天会话，智能体会保留先前工作的上下文，包括修改的组件、使用的样式方案和设置的本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得不错！现在再添加一个浅色模式开关，与高对比度开关并列。浅色模式应采用相同的模式，通过本地存储持久化设置，并放在用户界面（UI）的同一区域。用户应能分别启用高对比度和浅色模式。
    ```

2. 智能体会继续之前的工作，查看已做的更改并提出浅色模式的修改方案。
3. 与高对比度模式一样，逐项审查新编辑。使用 **Keep** 或 **Undo** 处理每项差异。
4. 如果智能体采取了不希望的方向（例如以不喜欢的方式重构开关 UI），可以选择聊天输入框旁的 **Stop** 按钮停止它，然后发送澄清后的后续消息。

> [!TIP]
> 引导进行中的会话比从头开始更快。可以用后续提示要求调整（“简化 CSS，改用 CSS 变量，不要重复选择器”）、纠正方向（“不要添加第三个开关，将浅色模式整合到现有设置面板中”）或扩展范围（“还为两个开关添加键盘快捷方式”）。

## 审查工作集

提交工作前，快速检查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 查看已更改文件的完整列表。应能看到 Astro 组件、样式和相关测试的更新。
3. 打开几个已更改文件并查看差异。确认其中采用了自定义智能体要求的无障碍模式，包括无障碍富互联网应用（ARIA）属性、键盘导航、语义 HTML 和本地存储持久化。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课将发布这些更改。

## 总结和后续步骤

你使用 Copilot Chat 智能体模式监控并引导了正在进行的会话：查看每项文件编辑、接受或拒绝更改，并在保留上下文的同时发送后续提示扩展工作。

本课介绍了以下内容：

- 实时监控智能体的工作。
- 接受和拒绝单项文件编辑。
- 使用后续提示引导正在进行的会话。
